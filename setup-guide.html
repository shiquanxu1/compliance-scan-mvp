◎ ComplianceScan 接入操作清单

从 Demo 到能真实收款的产品，只需在 Creem 与 Supabase 各做几步。下面每一步都配了界面示意，告诉你点哪里、复制什么。

⚠️ 说明：示意图为标注式占位（非真实后台截图），用于指引位置。各平台 UI 会更新，但入口与字段名基本一致。所有密钥都在你自己的账号后台获取，切勿发给他人。

1 Creem（收款 · 个人无需海外公司）

注册 https://www.creem.io → 建订阅产品 → 拿 API Key → 配 Webhook。用 test mode 可先跑通不扣费。

1注册并创建订阅产品

  1. 右上角 Sign up，用邮箱注册（支持大陆邮箱）。
  2. 左侧菜单进 Products → 点 New Product。
  3. 填：Name = Monitor Monthly，Price = 2.7（≈¥19），Billing = Monthly，类型选 Subscription。
  4. 保存后，产品页会显示一串 prod_xxx —— 这就是 Product ID。← 复制它
示意：Products → New Product

2获取 API Key（并注意 Test mode）

  1. 左侧进 Developers → API Keys。
  2. 复制 Secret Key（sk_xxx）。← 复制到 .env 的 CREEM_API_KEY
  3. 同一页右上角有 Test mode 开关：先打开它，并用页面提供的测试密钥（test 前缀）跑通，再切回生产密钥。
  4. 把 Product ID 与 Secret Key 填进 .env，设 CREEM_TEST_MODE=true。
示意：Developers → API Keys（右上角 Test mode）

3配置 Webhook（自动更新订阅状态）

  1. 左侧进 Developers → Webhooks → Add Endpoint。
  2. Endpoint URL 填：https://你的域名/api/webhook/creem（部署后才有域名，见部署指南）。
  3. 勾选订阅事件：subscription.paid、subscription.canceled 等。
  4. 创建后复制 Signing Secret（whsec_xxx）。← 填 CREEM_WEBHOOK_SECRET
  5. 服务端会验签后才写库；没配密钥则直接拒绝，安全。
示意：Developers → Webhooks

2 Supabase（注册 / 历史留存）

注册 https://supabase.com → 建项目 → 跑 SQL 建表 → 拿三个 Key。anon key 可公开，service_role 只在服务端用。

1新建项目

  1. GitHub 登录 Supabase → 点 New project。
  2. 填 Name（如 compliancescan）、设一个强密码（这是数据库密码，记好）、选区域（欧洲 frankfurt 更贴近用户）。
  3. 等 1–2 分钟初始化完成，进入项目控制台。
示意：New project

2执行建表 SQL

  1. 左侧 SQL Editor → New query。
  2. 把仓库里的 supabase-schema.sql 全文粘贴进去。
  3. 点 Run。它会建 scans / subscriptions 两张表并开启 RLS（行级安全，用户只看自己的数据）。
  4. 看到 "Success" 即完成。
示意：SQL Editor 粘贴并 Run

3复制三个 Key

  1. 左侧 Project Settings → API。
  2. 复制 Project URL → SUPABASE_URL。
  3. 复制 anon public → SUPABASE_ANON_KEY（可公开，前端用）。
  4. 复制 service_role secret → SUPABASE_SERVICE_KEY（仅服务端，勿进前端/仓库）。
  5. 填进 `.env` 或部署平台的环境变量，重启服务即可登录。
示意：Settings → API

环境变量汇总（填进 .env 或部署平台）

变量必填来自
CREEM_API_KEY收款必填Creem → Developers → API Keys（Secret）
CREEM_PRODUCT_ID收款必填Creem → Products（prod_xxx）
CREEM_TEST_MODE建议先 true，真实收款改 false
CREEM_WEBHOOK_SECRET建议Creem → Webhooks（whsec_xxx）
SUPABASE_URL历史必填Supabase → Settings → API
SUPABASE_ANON_KEY历史必填Supabase → API（anon public）
SUPABASE_SERVICE_KEY可选Supabase → API（service_role）
USE_PLAYWRIGHT可选false 默认；true 启用真浏览器扫描

不填任何密钥也能跑：扫描可用、结账走模拟、登录/历史为访客模式。按需在 .env / 平台后台逐个补即可。

配套文件：DEPLOY.md（部署到 Railway / Render）、scripts/test-creem.js 与 scripts/test-supabase.js（一键验证）。 部署与配置都需要你自己的账号，本清单只负责把"点哪里、复制什么"讲清楚。
