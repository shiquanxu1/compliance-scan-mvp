◎ ComplianceScan 部署图文分步

代码已初始化 git 并提交（b255eaa）。下面把仓库推到 GitHub 后，照图在 Railway 或 Render 点几下即可上线。两份指南任选其一。

✅ 已就绪：render.yaml / railway.json / Procfile 都已配好；服务默认用正则引擎，免费实例即可运行。示意均为标注式占位，非真实后台截图。

Railway 方案（推荐：自动分配节点 + 自带 HTTPS 域名）

免费档需绑卡验证（不扣费），每月 500 小时足够个人试水。

1新建项目并关联 GitHub

  1. 打开 railway.app → 用 GitHub 登录。
  2. 点 New Project → 选 Deploy from GitHub repo。
  3. 首次会请求 GitHub 授权，允许后能看到你的仓库列表。
示意：New Project → Deploy from GitHub repo

2选择本仓库并部署

  1. 在仓库列表里找到 compliance-mvp（或你的仓库名）。
  2. 点 Deploy。Railway 自动读 railway.json，用 node server.js 启动。
  3. 几秒后看到构建日志滚动，出现 ComplianceScan MVP 运行中 即成功。
示意：选仓库 → Deploy

3填入环境变量

  1. 进入项目 → Variables → New Variable。
  2. 逐个添加（也可批量粘贴 KEY=VALUE）：
    CREEM_API_KEY / CREEM_PRODUCT_ID / CREEM_TEST_MODE=true / CREEM_WEBHOOK_SECRET / SUPABASE_URL / SUPABASE_ANON_KEY / SUPABASE_SERVICE_KEY。
  3. 保存后 Railway 会自动重启服务使变量生效。
示意：Variables 添加键值对

4生成公网域名

  1. 进入项目 → Settings → Domains → 点 Generate Domain。
  2. 得到一个 xxx.up.railway.app（自带 HTTPS）。
  3. 打开它即可访问你的站点。
  4. 想要自己的域名：在此填自定义域名，去 DNS 加一条 CNAME。
示意：Settings → Domains → Generate

Render 方案（有免费档，冷启动稍慢）

Free 档实例闲置后会休眠，首次访问需几秒唤醒；付费档（$7/月起）常驻。

1新建 Blueprint 并连仓库

  1. 打开 render.com → 用 GitHub 登录。
  2. 点 New → Blueprint。
  3. 连接 GitHub 仓库，选 compliance-mvp。Render 自动读取 render.yaml。
示意：New → Blueprint → 选仓库

2确认构建/启动命令

  1. Blueprint 预览里会显示服务名 compliancescan。
  2. 确认 Build Command = npm install、Start Command = node server.js（来自 render.yaml）。
  3. 点 Apply 开始首次部署。
示意：确认命令 → Apply

3填写环境变量

  1. 部署页 → Environment → 添加变量。
  2. 同 Railway：CREEM_* 与 SUPABASE_* 七个变量（见 Railway 第 3 步）。
  3. 保存后重新部署（手动 Redeploy 或自动）。
示意：Environment 添加变量

4拿到 .onrender.com 域名

  1. 部署完成后，Render 分配 xxx.onrender.com（自带 HTTPS）。
  2. 点进去即可访问。
  3. 自定义域名在 Settings → Custom Domains 绑定。
示意：部署完成 → 得到 onrender.com 域名

部署后必做：接通 Creem Webhook（两平台通用）

  1. 拿到你的公网域名后，去 Creem 后台 Developers → Webhooks 新建端点。
  2. Endpoint URL 填：https://你的域名/api/webhook/creem（如 https://compliancescan.up.railway.app/api/webhook/creem）。
  3. 勾选事件 subscription.paid / subscription.canceled。
  4. 复制 Signing Secret（whsec_xxx）→ 加到平台环境变量 CREEM_WEBHOOK_SECRET 并 redeploy。
  5. 服务端已对原始 body 做 HMAC-SHA256 验签，验签失败直接拒绝，安全。

本地联调 Webhook：用 ngrok 把 localhost:3000 暴露成公网地址，再在 Creem 指向它即可。

配套：DEPLOY.md（文字版）、setup-guide.html（Creem/Supabase 接入）、scripts/test-*.js（一键验证）。 部署与配置均在你自己的账号后台完成，本指南只负责把"点哪里"讲清楚。
