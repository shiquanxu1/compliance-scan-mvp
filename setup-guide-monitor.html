一、合规文档生成（无需任何密钥，已可用）

🎁 文档生成功能不依赖外部服务：基于扫描结果在本地生成隐私政策 / Cookie 声明 / DPA 草稿。你只需要在界面上点「📄 生成合规文档」并填表即可体验，跳过本节。

若想把它接到真实站点对外服务，只需确保站点已部署、能访问 /api/generate-doc（见文末部署提醒）。

二、每日监控所需密钥配置

每日监控 = 服务端定时重扫 + 违规邮件告警，需要 3 类配置：Supabase（已建表）、Resend（发信）、CRON_SECRET / SITE_URL（定时任务保护与回跳）。

1注册 Resend 并获取 API Key（告警邮件发送）

用途：监控发现合规回退时，向用户发告警邮件。未配置时告警仅打印日志，便于本地调试。

① 打开 resend.com → Sign Up → 进入 Dashboard
② 左侧 API Keys → Create API Keyre_xxxxxxxx
③ 左侧 Domains → 添加并验证你的发件域名（或用官方 sandbox 域名测试）
↓ 复制 填入 .env：RESEND_API_KEY=re_xxx
# .env
RESEND_API_KEY=re_你的密钥
FROM_EMAIL=ComplianceScan <notifications@你的域名.com>

2设置 CRON_SECRET 与 SITE_URL

用途：CRON_SECRET 保护每日监控接口（防止外人手动触发你花钱扫描）；SITE_URL 用于支付回跳与告警邮件「查看详情」按钮。

生成强随机串（本地终端执行）openssl rand -hex 32
↓ 填入 .envCRON_SECRET=随机串
↓ 填入 你的公网域名SITE_URL=https://你的域名.com
# .env
CRON_SECRET=$(openssl rand -hex 32)
SITE_URL=https://your-domain.com
⚠️ 若用 Railway/Render 部署，这些变量要填进对应平台的 Environment / Variables，而不是本地 .env。

3GitHub Actions Secrets（让每日 cron 能调通你的服务）

用途：仓库里的 .github/workflows/monitor.yml 每天 UTC 02:00 自动 POST 你的 /api/cron/monitor。它需要在请求头带 Bearer CRON_SECRET，且要知道你的 SITE_URL。

① 打开 GitHub 仓库 → Settings → Secrets and variables → Actions
② New repository secret → Name=SITE_URLhttps://你的域名.com
③ 再建一个 → Name=CRON_SECRET（与 .env 里一致）同步骤2的串
↑ 工作流自动读取 无需改代码
# .github/workflows/monitor.yml 关键片段（已存在）
- name: Trigger daily monitor
  run: |
    curl -X POST "${{ secrets.SITE_URL }}/api/cron/monitor" \
      -H "Authorization: Bearer ${{ secrets.CRON_SECRET }}"
🕑 频率：默认每天一次（UTC 02:00）。可在 monitor.yml 的 cron: 字段改成每天多次或仅工作日。

4本地手动验证（不依赖 GitHub）

用途：上线前先确认监控链路跑得通。注意本地脚本直接调用核心函数，不检查 CRON_SECRET；只有 HTTP 接口才检查。

# 本地 .env 已填 SUPABASE_SERVICE_KEY（+可选 RESEND_API_KEY）
node scripts/monitor.js

# 预期输出（无 RESEND 时）：
# [monitor] 已扫描 N 个监控项，触发 M 次告警（无 RESEND_API_KEY 仅日志）
# 或在 .env 设好 CRON_SECRET 后模拟接口调用：
curl -X POST http://localhost:3000/api/cron/monitor \
  -H "Authorization: Bearer $CRON_SECRET"
✅ 验证通过标志：Supabase 的 monitors 表 last_score / score_history 被更新；配置了 Resend 时收件箱收到告警邮件（评分下降或新增违规时）。

三、环境变量汇总表

变量必需作用在哪填
SUPABASE_URL✅数据库地址（监控读取/回写）.env / 平台变量
SUPABASE_SERVICE_KEY✅服务端读 monitors/subscriptions、回写评分.env / 平台变量
SUPABASE_ANON_KEY✅前端登录/历史（RLS 隔离）.env / 平台变量
RESEND_API_KEY⚠️ 建议发送告警邮件；缺省则仅日志.env / 平台变量
FROM_EMAIL⬜发件人显示.env / 平台变量
CRON_SECRET✅保护 /api/cron/monitor 接口.env / 平台变量 + GitHub Secret
SITE_URL✅支付回跳 + 邮件「查看详情」+ cron 目标.env / 平台变量 + GitHub Secret
USE_PLAYWRIGHT⬜true=真浏览器扫描（监控也受益）.env / 平台变量
支付相关⬜Creem/Paddle/Stripe（见支付配置清单）.env / 平台变量

四、监控体验链路（上线后）

  • 用户注册登录 → 扫描某站点 → 点「🔔 加入每日监控」→ 写入 monitors 表。
  • GitHub Actions（或系统 cron）每天触发 /api/cron/monitor → 重扫 → 评分下降/新增违规则 Resend 发精美告警邮件。
  • 用户在「每日监控站点」列表点「📈 查看趋势」→ 前端读取 score_history 渲染 SVG 折线图（含及格线 80）。
📌 部署提醒：GitHub Actions 调的是公网 https://你的域名.com，所以请先完成 DEPLOY.md 的部署与 Creem/Supabase 配置，再配本页的监控密钥。
